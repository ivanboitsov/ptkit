# ptkit: документация

Oct 13, 2026 · @Ivan Boytsov

## Что такое ptkit

ptkit — неофициальная Python-библиотека для работы с API продуктов Positive Technologies. Первая цель — MaxPatrol VM: подключение по токену, выполнение PDQL-запросов, построитель запросов и чтение активов, групп и задач сканирования.

Библиотека снимает с разработчика интеграций повторяющуюся работу: авторизацию, разбор ответов, потоковую выгрузку больших результатов, обработку ошибок и сборку PDQL-строк вручную.

**Статус:** проектная документация. API ещё не реализован и может меняться; примеры PDQL в документе приблизительные и будут сверены с документацией MaxPatrol VM.

**Чем ptkit не является:**

- не официальный продукт Positive Technologies и не связан с компанией;
- не приложение: синхронизация данных, отчёты, уведомления и расписания строятся поверх библиотеки в ваших проектах;
- в первой версии не меняет данные в MaxPatrol: только чтение.

## Установка

Требования: Python 3.9 или новее и одна зависимость, `requests`.

С доступом к PyPI:

```bash
pip install ptkit
```

В закрытом контуре без интернета: скачайте на машине с доступом в сеть wheel-файлы ptkit и зависимостей, перенесите их в контур и установите из локального каталога.

```bash
# на машине с интернетом
pip download ptkit -d ./wheels

# в закрытом контуре
pip install --no-index --find-links ./wheels ptkit
```

Каждый релиз на GitHub содержит готовый архив wheel-файлов со всеми зависимостями, чтобы этот шаг можно было пропустить.

## Быстрый старт

Выпустите токен доступа в MaxPatrol VM для сервисной учётной записи с правами только на чтение. Дальше достаточно адреса сервера и токена.

```python
from ptkit.vm import Client

with Client("https://mp.example.local", token="<ваш токен>") as mp:
    for row in mp.pdql("select(@Host, Host.@id) | limit(10)"):
        print(row)
```

Что здесь происходит:

1. `Client` проверяет адрес и готовит подключение; запросы ещё не отправлены.
2. `mp.pdql(...)` возвращает итератор. Запрос уходит в MaxPatrol только тогда, когда цикл `for` просит первую строку.
3. Строки приходят по мере выгрузки, весь результат не держится в памяти.
4. Выход из блока `with` закрывает соединения.

## Клиент и подключение

`Client` — единственная точка входа в API. Все ресурсы (активы, группы, задачи) доступны как его атрибуты.

| Параметр | Тип | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `base_url` | `str` | обязателен | Адрес MaxPatrol Core, например `https://mp.example.local` |
| `token` | `str` | обязателен | Токен доступа, выпущенный в MaxPatrol |
| `verify` | `bool` или `str` | `True` | Проверка сертификата; строка = путь к корневому сертификату организации |
| `timeout` | `float` | `30` | Таймаут одного HTTP-запроса, секунды |
| `retries` | `int` | `3` | Число повторов при сетевой ошибке и ответах 5xx |
| `backoff` | `float` | `1.0` | Начальная пауза между повторами, удваивается с каждой попыткой |

Токен не обязательно передавать в коде. Если параметр не указан, клиент берёт его из переменной окружения `PTKIT_TOKEN`, а адрес из `PTKIT_URL`.

```python
from ptkit.vm import Client

mp = Client.from_env(verify="/etc/ssl/corp-ca.pem")
print(mp.version())   # версия MaxPatrol VM на сервере
mp.close()
```

Третий способ — конфигурационный файл. Удобен, когда настройки общие для нескольких скриптов.

```python
mp = Client.from_config("ptkit.toml")
```

```toml
# ptkit.toml
url = "https://mp.example.local"
token = "..."
verify = "/etc/ssl/corp-ca.pem"
timeout = 30
```

Глобального конфига у библиотеки нет намеренно: каждый `Client` хранит свои настройки, поэтому в одной программе можно работать с несколькими инсталляциями MaxPatrol, а тесты не влияют друг на друга. Файл с токеном храните с правами только для владельца (`chmod 600`).

Не отключайте проверку сертификата (`verify=False`) в рабочих системах: токен даёт доступ к данным об уязвимостях всей организации. Укажите путь к корневому сертификату, которым подписан сертификат MaxPatrol.

## PDQL

Запрос в ptkit можно задать двумя способами: готовой строкой PDQL или через построитель. Оба возвращают один и тот же ленивый итератор.

### Сырой PDQL

Подходит, когда запрос уже отлажен в интерфейсе MaxPatrol: его можно вставить как есть.

```python
query = "select(@Host, Host.@id, Host.OsName) | limit(100)"
for row in mp.pdql(query, group_id="<id группы>"):
    print(row["Host.OsName"])
```

`group_id` необязателен и ограничивает запрос группой активов. Ограничение группой заметно ускоряет запросы на больших инсталляциях.

### Построитель запросов

Построитель собирает строку PDQL из цепочки методов. Поля описаны как атрибуты классов (`Host.id`, `Host.name`), поэтому опечатка в имени поля видна в редакторе кода, а не в ответе сервера.

```python
from ptkit.vm import Host

query = (
    mp.assets.query()
    .select(Host.id, Host.name, Host.os_name)
    .filter(Host.os_name.contains("Windows") & (Host.importance == "high"))
    .sort(Host.name)
    .limit(500)
)

print(query.to_pdql())   # строка, которая уйдёт в MaxPatrol
for host in query:       # запрос выполняется здесь
    print(host.name)
```

Методы построителя:

| Метод | Что делает |
| --- | --- |
| `select(*fields)` | Какие поля вернуть |
| `filter(condition)` | Условие отбора; несколько вызовов объединяются через «и» |
| `sort(field, desc=False)` | Сортировка |
| `limit(n)` | Ограничение числа строк |
| `in_group(group_id)` | Ограничение группой активов |
| `to_pdql()` | Итоговая строка PDQL без выполнения |

Условия строятся операторами Python: `==`, `!=`, `<`, `<=`, `>`, `>=`, объединяются через `&` (и), `|` (или), `~` (не). Для строк и списков есть методы `contains`, `startswith`, `in_`.

Безопасность: значения в условиях всегда экранируются. Строка из пользовательского ввода, переданная в `filter`, не может изменить структуру запроса.

Построитель покрывает основные конструкции PDQL, а не весь язык. Если нужна конструкция, которой в нём нет, используйте сырой запрос: это штатный путь, а не обходной.

## Ресурсы

В первой версии три ресурса, все только на чтение.

| Ресурс | Методы | Возвращает |
| --- | --- | --- |
| `mp.assets` | `query()`, `get(asset_id)` | `Asset` |
| `mp.groups` | `list()`, `tree()`, `get(group_id)` | `Group` |
| `mp.tasks` | `list()`, `get(task_id)`, `runs(task_id)` | `ScanTask`, `TaskRun` |

```python
asset = mp.assets.get("<id актива>")
print(asset.name, asset.os_name)

for group in mp.groups.list():
    print(group.id, group.name)

for run in mp.tasks.runs("<id задачи>"):
    print(run.started_at, run.status)
```

Все объекты — лёгкие типизированные классы с полями, которые библиотека знает. Полный исходный ответ сервера всегда доступен через `.raw`: схема данных меняется между версиями MaxPatrol, и поля, которые библиотека пока не описала, не должны теряться.

```python
print(asset.raw.keys())   # все поля из ответа MaxPatrol
```

## Ошибки и журналирование

Все исключения библиотеки наследуются от `PtkitError`, поэтому их можно поймать одним `except`, а при необходимости разобрать по типам.

| Исключение | Когда возникает |
| --- | --- |
| `AuthError` | Токен неверный, отозван или истёк (HTTP 401, 403) |
| `NotFoundError` | Объект с таким id не существует (HTTP 404) |
| `PDQLError` | MaxPatrol отклонил запрос: синтаксис, неизвестное поле |
| `TimeoutError` | Сервер не ответил за отведённое время после всех повторов |
| `ServerError` | Ошибка на стороне MaxPatrol (HTTP 5xx) после всех повторов |
| `UnsupportedVersionError` | Функция недоступна в версии MaxPatrol на сервере |

```python
from ptkit import AuthError, PDQLError, PtkitError

try:
    rows = list(mp.pdql(query))
except AuthError:
    print("Проверьте токен")
except PDQLError as e:
    print("Ошибка в запросе:", e.message)
except PtkitError as e:
    print("Другая ошибка:", e)
```

Журналирование идёт через стандартный модуль `logging`, логгер называется `ptkit`. Библиотека ничего не печатает сама и не настраивает обработчики: это решает приложение.

```python
import logging
logging.getLogger("ptkit").setLevel(logging.DEBUG)
```

На уровне `DEBUG` в журнал попадают адреса запросов, время выполнения и размер ответа. Токен никогда не записывается в журнал ни на каком уровне.

## Совместимость с версиями MaxPatrol

API MaxPatrol VM общий с веб-интерфейсом и меняется вместе с продуктом, поэтому ptkit явно указывает, с какими версиями он проверен.

| Версия ptkit | Проверено с MaxPatrol VM |
| --- | --- |
| 0.1 | 2.7 |

При подключении клиент узнаёт версию сервера. Если она не проверялась с текущей версией ptkit, в журнал пишется предупреждение, но работа не блокируется: большинство запросов переживает обновления без изменений.

Всё, что зависит от версии (адреса запросов, имена полей), собрано в одном модуле `ptkit.vm._compat`. Поддержка новой версии MaxPatrol означает правку этого модуля и записанных ответов для тестов, а не всей библиотеки.

Если вы работаете с версией, которой нет в таблице, и библиотека у вас работает, сообщите об этом в issue: так таблица растёт.

## Структура пакета и разработка

Пакет разделён на общую часть и модули продуктов. Общая часть (транспорт, ошибки, PDQL) не знает про конкретный продукт, поэтому `ptkit.siem` позже добавится рядом с `ptkit.vm` без переделки ядра.

```text
ptkit/
    __init__.py          # публичные исключения
    errors.py            # PtkitError и наследники
    _http.py             # сессия, токен, повторы, сертификаты
    pdql/
        fields.py        # описание полей и операторы условий
        builder.py       # построитель запросов, to_pdql()
        escape.py        # экранирование значений
    vm/
        client.py        # Client, from_env(), version()
        assets.py        # mp.assets, Asset, Host
        groups.py        # mp.groups, Group
        tasks.py         # mp.tasks, ScanTask, TaskRun
        _compat.py       # всё, что зависит от версии MaxPatrol
    py.typed             # маркер типизации для IDE и mypy
tests/
    fixtures/            # записанные ответы API, по версиям
    unit/                # тесты без сети
    live/                # тесты на живом MaxPatrol, по желанию
```

### Тесты

Публичного стенда MaxPatrol нет, поэтому основной набор тестов работает без сервера:

- построитель PDQL проверяется сравнением результата `to_pdql()` с ожидаемой строкой;
- клиент и ресурсы проверяются на записанных ответах API из `tests/fixtures/`;
- живые тесты в `tests/live/` запускаются только при заданных `PTKIT_URL` и `PTKIT_TOKEN` и только на чтение.

```bash
pytest tests/unit          # без сервера
pytest tests/live          # нужен доступ к MaxPatrol
```

### Вклад в проект

- Записанные ответы API перед добавлением в репозиторий очищаются от реальных имён хостов, IP-адресов и идентификаторов вашей организации.
- Новый метод API сопровождается записанным ответом и unit-тестом.
- Сообщение об ошибке включает версию ptkit, версию MaxPatrol и, если дело в запросе, результат `to_pdql()`.
- Лицензия MIT.

## Дорожная карта

Версии идут по порядку; каждая следующая начинается, когда предыдущая используется хотя бы в одном реальном проекте.

1. **0.1 — чтение MaxPatrol VM.** Клиент с токеном, сырой PDQL, построитель запросов, активы, группы, задачи сканирования, иерархия ошибок.
2. **0.2 — шире PDQL и данные.** Агрегации в построителе, уязвимости как отдельный ресурс, выгрузка в CSV и JSON одной функцией.
3. **0.3 — асинхронный клиент.** `AsyncClient` с тем же интерфейсом для приложений на asyncio (например, FastAPI); логика запросов общая с синхронным клиентом.
4. **0.4 — MaxPatrol SIEM.** Модуль `ptkit.siem` поверх общего ядра: события, инциденты, табличные списки.
5. **1.0 — стабильный API.** Публичный интерфейс зафиксирован, несовместимые изменения только в следующей мажорной версии.

Запись в MaxPatrol (изменение активов, запуск сканирований) не запланирована до 1.0: ошибка в записи может повредить данные рабочей системы ИБ, и такие функции требуют отдельного обсуждения.
